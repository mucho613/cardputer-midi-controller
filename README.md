# Cardputer MIDI Controller

初代 **M5Stack Cardputer (K132)** と **Unit MIDI (U187 / SAM2695)** 用のファームウェアです。
外部 MIDI キーボードやシーケンサーの16チャンネルを音源へ転送し、Cardputer で音色・音量・パン・リバーブ量・コーラス量を変更します。

音作り画面では **カットオフ・レゾナンス・アタック・リリース** もチャンネル別に変更でき、8つのプリセットに保存できます。

## 配線と音声出力

電源を切ってから次のように接続してください。

1. Cardputer と Unit MIDI の Grove 端子を付属ケーブルで接続します。
2. Unit MIDI のスイッチを **Bypass** にします。
3. 外部機器の **MIDI OUT → Unit MIDI の MIDI IN** を接続します。最初は DIN 5ピンケーブルで確認してください。
4. Unit MIDI の **AUDIO OUT → 外部アンプ／アクティブスピーカーの音声入力** を接続します。音量を小さくしてから確認してください。
5. Cardputer を USB 給電し、本体電源を ON にします。

```text
鍵盤／シーケンサー MIDI OUT
          │ DIN MIDI
          ▼
Unit MIDI IN ── Grove 白 / GPIO1 RX ──► Cardputer
                                          │ 受信・解析・画面・キー操作
SAM2695     ◄── Grove 黄 / GPIO2 TX ────────┘
   │
   └── AUDIO OUT ──► アンプ／アクティブスピーカー
```

| ケーブル | Cardputer | 用途 |
|---|---|---|
| 黒 | GND | 共通グランド |
| 赤 | 5V | ユニット給電 |
| 黄 | GPIO2 / UART TX | Cardputer → SAM2695 |
| 白 | GPIO1 / UART RX | 外部 MIDI IN → Cardputer |

Bypass は **MIDI IN → MIDI OUT** のハードウェアスルーです。内蔵音源を直接鳴らすバイパスではありません。このファームウェアが入力を受信し、音源へ転送します。本体で行った変更は Bypass 時の MIDI OUT には出ません。Separate は今回の標準構成では使用しません。

音源の音は Cardputer の内蔵スピーカーからは出ません。MIDI 用の3.5mm端子と **AUDIO OUT** は別物です。TRS MIDI を使用する場合は、機器・ケーブルの結線仕様を先に確認してください。

通信は **31,250 bps / 8N1** です。商品説明の `31520` 表記とは異なりますが、メーカーの Arduino 実装の `MIDI_BAUD 31250` を採用しています。

## Windows でビルド・USB書き込み

### 開発環境

推奨は VS Code と **PlatformIO IDE** 拡張です。このフォルダを開き、PlatformIO の **Build** でビルド、**Upload** で書き込みできます。初回はツールチェーンとライブラリのダウンロードが必要です。

PowerShell で操作する場合、PlatformIO のインストール先が既定なら以下を使用できます。

```powershell
$pio = "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe"
& $pio run
& $pio device list
```

Cardputer をデータ通信対応の USB-C ケーブルで接続し、`device list` で該当する COM ポートを確認します。以下の `COM7` は例なので、**実際の Cardputer のポートに置き換えてください**。

```powershell
& $pio run -t upload --upload-port COM7
& $pio device monitor --port COM7 --baud 115200
```

書き込みできない場合は、本体を OFF にし、**G0 ボタンを押しながら ON** にしてダウンロードモードへ入り、再度ポートを確認して書き込みます。書き込み後は再起動します。シリアルモニターを開いたまま書き込めない場合は先に閉じてください。

- 対象環境: `cardputer`、ESP32-S3、8MBフラッシュ、Arduino framework。
- ESP32 platform と全ライブラリの直接依存は `platformio.ini` で固定しています。
- ビルド出力: `.pio/build/cardputer/firmware.bin`。これはアプリ領域用です。初回書き込みは bootloader・partition table も扱う PlatformIO Upload を使ってください。
- 書き込みは既存アプリを置き換えます。通常の Upload は NVS プリセットを保持しますが、フラッシュ全消去では保存内容も消えます。
- USB は書き込みと診断ログ用です。USB MIDI 機能はありません。

## 初回動作確認

1. 起動すると初期設定、または最後に保存／読み込みしたプリセットが送られます。初期化中は演奏を開始せず、1秒程度待ちます。
2. **Space** を押します。選択チャンネルで約250msの試聴音が鳴ります。CH10 はバスドラム、それ以外は中央ドです。
3. 外部鍵盤を MIDI CH1 にし、弾いて離します。受信表示の1番が点灯し、離鍵で音が止まることを確認します。
4. `,` / `/` で音色を変更し、音と画面の両方が変わることを確認します。
5. MIDI データを複数チャンネルで再生し、`[` / `]` で各パートを選んで確認します。

画面の受信表示は **MIDI チャンネルメッセージの受信活動** です。音声レベルや実際の発音数ではありません。音源からの設定読み返しや接続確認応答はないため、ケーブル未接続でも設定値は画面に表示されます。

## キー操作

| キー | 通常画面 |
|---|---|
| `[` / `]` | 選択チャンネル 1〜16 |
| `;` / `.` | 編集項目を前／次へ |
| `,` / `/` | 値を −1 / ＋1（押し続けてリピート） |
| Shift + `,` / `/` | 値を −10 / ＋10 |
| `T` | BASIC（基本5項目）／TONE（音作り4項目）の切り替え |
| Space | 選択チャンネルで短く試聴 |
| Backspace | 全チャンネルのサステイン解除・All Sound Off・All Notes Off |
| `P` | プリセット画面を開閉 |
| `H` | キーガイドを開閉 |

キーは物理位置で認識するため、Shift で記号が変わっても操作できます。矢印キー用の Fn は不要です。表示ラベルは英語です。

`T` で切り替えた各画面では、`;` / `.` がその画面内の項目を巡回します。画面ごとに最後の選択項目を保持し、選択チャンネル・試聴・全音停止・プリセット操作は共通です。

| TONE項目 | 内容 | 初期値 |
|---|---|---|
| CUTOFF（CF） | フィルターのカットオフ調整 | 64 |
| RESONANCE（RS） | フィルターのレゾナンス調整 | 64 |
| ATTACK（AT） | 音の立ち上がり時間の調整 | 64 |
| RELEASE（RL） | 離鍵後の減衰時間の調整 | 64 |

4項目とも範囲は **0〜127**、**64が音色本来の設定（64 = original）** です。Hzや秒数の直接指定ではありません。効き方は音色に依存し、音色やドラムによって変化が小さい場合もあります。外部または本体で音色を変えた際は、確定済みの4項目を新しい音色へ再送して維持します。

- PROGRAM は画面で **1〜128**、MIDI上では **0〜127**。本体からの音色選択は Bank MSB/LSB を0にして GM 音色を選びます。
- VOLUME / PAN / REVERB / CHORUS は **0〜127**。PAN の64が中央です。リバーブ・コーラスは各チャンネルのセンド量を変更し、エフェクト種類は初版では編集しません。
- CH10 は `DRUM` と表示し、通常楽器名を誤表示しません。ドラムキットはプログラム番号で表示します。
- 外部 Bank Select は次の Program Change で確定する音色バンクとして追跡します。Bank 0:0以外は名前を推測せず番号で表示します。
- 外部からの Program Change / 対象 CC と本体操作は、転送順に最後の変更が優先されます。
- `?` は未確定の値です。未対応 SysEx やリセット受信、通信異常で状態を保守的に未確定にします。該当項目を編集すると、その項目を再設定できます（未確定時は初期値を基準に増減）。音源モードも未確定の間は楽器名を推測せず、プリセット保存を止めます。全項目とモードを確定するにはプリセットを読み込みます。
- SysEx や未完了メッセージ中の設定変更は待機します。連続操作は有限キューに入り、満杯の場合は `Command queue full` を表示します。
- 全音停止はその時点の音を止めます。その後届く新しい Note On は通常どおり演奏します。

## 8つのプリセット

`P` を押し、`[` / `]`（または `,` / `/`）でスロットを選びます。

| 操作 | 動作 |
|---|---|
| Enter | 選択スロットを読み込み |
| `S` | 現在の16チャンネル分の設定を保存 |
| 上書き確認の Enter / `Y` | 保存確定 |
| 上書き確認の `N` / `P` / バッククォート | 保存取り消し |
| Backspace | 読み込み待機を取り消し、全音停止 |

保存項目は各チャンネルの **適用済みバンクMSB/LSB、プログラム、音量、パン、リバーブ量、コーラス量** です。ノート、サステイン、ピッチベンド、Expression、マスター音量、エフェクト種類などは保存しません。

バージョン2では、これらに **カットオフ、レゾナンス、アタック、リリース** を加えた11項目を各チャンネルに保存します。旧バージョン1のプリセットもそのまま読めます。既存7項目は保持し、追加4項目を64で補います。読み込みだけでは保存データを書き換えず、手動保存した時点でバージョン2になります。旧ファームウェアへの逆方向の互換性はありません。

読み込み時は全音停止 → GM System On → 初期化待機 → 設定送信を行います。GMリセットにより保存対象外の設定も音源の初期状態へ戻ります。演奏を止めてから読み込んでください。入力・送信が継続している場合は待機します。

起動時には最後に正常に保存／読み込みしたスロットを復元します。`P1*` の末尾の `*` は保存／読み込み時点から変更されたことを表します。外部 MIDI による変更も手動保存するまで永続化しません。プリセット一覧の番号横の `*` は現在選択されている起動スロットです。

未保存・破損・形式非互換のスロットは初期値へフォールバックし通知します。元の破損データは勝手に上書きしません。未確定の値を含む状態は保存できません。`Busy: retry save` の場合は MIDI 入力を止めて再試行してください。

初期値は Bank 0:0 / Program 1（CH10 は標準ドラム）、音量100、パン64、リバーブ40、コーラス0です。保存形式は固定長バイト列＋バージョン＋CRC32で、Preferences/NVS に保存します。

## OUTPUT LEVEL（本体共通の出力レベル）

`O`で専用画面を開閉し、`,`／`/`で1 dB、Shift併用で10 dBずつ調整します。範囲は**−40〜0 dB**、初回・未保存・保存データ不正時は**−40 dB**です。`S`で手動保存し、`SAVED`表示を確認してから電源を切ってください。変更後は`UNSAVED`と表示します。保存が`Busy`の場合は演奏を止めて再度Sを押してください。`Enter`は現在値の再送、Spaceは試聴、Backspaceは全音停止です。

SAM2695のCodec Control 0のOUTG（DACアナログ出力ゲイン）を調整します。MIDI Master Volume・CC7・CC11・各パートのバランスとは独立しています。0 dBは減衰なしであり、無音ではありません。画面は送信設定値で、実測値ではありません。

専用NVS名前空間`card-output`の`level`に、バージョン・範囲・反転値の整合性検証を持つ8バイト形式で保存します。書き込み後に読み戻し検証します。プリセット形式は変更せず、プリセット保存／読み込みでもOUTPUT LEVELは変わりません。未保存値も、現在の起動中は音源リセット後に再適用します。

起動時は外部演奏の転送前に設定します。プリセット読み込みのGMリセット、外部GM/GS/XGリセット、System Reset（FF）、Reset All NRPN（37:5F、Data Entry=45、いずれも16進）を検出すると、送信末尾から200 ms待機して出力レベルを再送し、後続メッセージを流します。連続リセットも各待機境界を保持します。外部Codec Control 0変更にも同様に本体設定を再適用します。SysEx途中には設定を挿入せず、終了または通信異常からの復帰を待ちます。

ユニット単体の電源入れ直しやハードウェアリセットはUARTから検出できません。その場合は`O`→`Enter`で再適用してください。電源投入・リセットから再設定完了までの出力やポップノイズはソフトウェアだけでは保証できません。ヘッドホンは設定後に装着し、−40 dBから確認してください。

[メーカーSAM2695資料のCodec Control（36ページ）](https://m5stack.oss-cn-shenzhen.aliyuncs.com/resource/docs/products/unit/Unit-Synth/SAM2695.pdf#page=36)に基づき、`F0 00 20 00 00 00 12 33 77 12 vv3 vv2 vv1 vv0 00 F7`を送信します。他のビットは資料の初期値とし、−40 dBで`0x1B51`、0 dBで`0x1B79`です。正のゲインと、1 dB刻みにならない−40 dB未満は公開しません。

追加のホストテストでは出力バイト列、上下限、保存／破損復帰、プリセットとの独立性、SysEx競合、Running Status復元、連続リセットの待機、キュー容量不足を検証します。音量・画面・NVSの電源再投入後の復元は実機未確認です。

- [ ] O画面の初回−40 dB、1/10 dB調整、上下限と音量変化が正常。
- [ ] Sで保存後に再起動して復元し、プリセット切替でも維持する。
- [ ] 外部リセット後にレベルが戻り、後続の演奏を再開する。
- [ ] ユニット単体の再起動後、O→Enterで再適用できる。

## MIDI処理と制限

- Running Status を解釈し、出力側でも再構成します。本体操作でステータスが変わっても、次の外部データに必要なステータスを付け直します。
- リアルタイムメッセージはチャンネルメッセージや SysEx の途中でも扱います。通常メッセージは完了単位で、本体操作はその境界で転送します。
- SysEx は全体をメモリに保持せずストリーミング転送します。長い SysEx でも送信が追い付く限り処理できます。未知の SysEx は転送しますが、画面の状態は未確定にします。
- 音作り4項目はNRPN（MSB=1、LSB=カットオフ0x20／レゾナンス0x21／アタック0x63／リリース0x66）で制御します。外部のRPN/NRPN選択を追跡し、本体操作は一組の送信として扱ってから元の選択状態へ戻します。外部の対象NRPN＋CC6も画面・保存内容に反映します。未完了の選択を推測せず、未対応のData Entry LSBや増減指示は転送したうえで対象値を未確定にします。
- 受信UARTバッファ2KB、送信統合バッファ4KB、本体コマンド512件の有限キューを使用します。NRPN操作は1コマンドとして登録し、送信時に必要なCC列へ展開します。画面は最大20fpsです。
- UARTエラー、バッファ超過、データ途中の100ms無通信、SysEx途中の500ms無通信を検出します。Active Sensing を受信した場合だけ、330ms無通信でも消音復帰します。Active Sensing のない鍵盤のケーブル抜去は検知できないため、Backspace で消音してください。
- 異常時は残っている送信を流し、SysEx終端と全音停止を送ります。復帰中の入力・未送信の本体操作は破棄し、画面に `MIDI ERR` を表示します。エラー回数は再起動まで残ります。プリセット読み込みで設定を再確定できます。
- 入力と出力は同じ転送速度です。最大帯域での入力に本体操作を大量追加すると、遅延増加やキュー超過が起こり得ます。無限の帯域・ゼロ遅延は保証しません。
- 内蔵試聴と外部演奏が同じチャンネル・同じノートで重なった場合、音源のノート割当仕様により外部音にも影響する場合があります。試聴は演奏停止中を推奨します。

## 自動テスト

MIDI コアと保存形式は Arduino に依存せず、ホストPCで検証できます。CMake、C++17コンパイラが必要です。Windows の MinGW の例:

```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
ctest --test-dir build --output-on-failure
```

Linux/macOS ではジェネレーター指定を省略できます。Visual Studio の場合はそのジェネレーターを使用し、`ctest --test-dir build -C Debug --output-on-failure` で実行します。

テストは16チャンネルの状態管理、バンク確定、外部／本体操作の順序、Running Status、リアルタイム割り込み、各種メッセージ転送、SysExと本体操作の競合、タイムアウト・Active Sensing・時間カウンター周回、バッファ超過、長いSysEx、試聴の離鍵、GMリセット送信間隔、保存データの各バイト破損と初期値復帰を検証します。
